Checking accessibility as interaction unfolds.

A11yLTLNav checks temporal properties of interface interactions to find navigation failures affecting blind and low-vision screen-reader users.

02 / The approach

From navigation failures
to executable checks.

Accessibility expectations become explicit properties that can be checked across interface interactions.

  1. 01

    Learn from prior studies

    Organize navigation failures documented in prior research with blind and low-vision users into a failure taxonomy.

  2. 02

    Specify expected behavior

    Translate browser-observable failures into Linear Temporal Logic (LTL) properties over sequences of actions and states.

  3. 03

    Explore and check

    Generate keyboard interaction traces and monitor the properties, connecting each report to the behavior that violated an expectation.

Example expectation

When a dialog opens, keyboard focus should move inside it.

The checker evaluates the transition between relevant interface states.
