Executive Summary

结论：主干方法每 2–3 个月就有新的 SOTA，而且都只在 EMDB/RICH/3DPW 上报告整体数字，没有一篇按遮挡、人物大小、相机转速这些因子做可控评测。

L2. 遮挡与后处理：方法多，评测粗

  • 生成式先验：MoRo（2601.16079 ✅，掩码建模）、MoPO（2605.09856 ✅，时空遮挡检测器预测关节可见性，再用运动预测补全）、RoHM（2401.08570 ✅）、FactorizedHMR。
  • 后处理与优化：HTD-Refine（2605.26879 ✅，CVPR 2026 oral，用估计的速度和加速度做软约束）、PromptHMR 后优化、AHa-3D v2。
  • 局部证据精修（新）：FootMR（2603.09681 ✅，从 2D 脚部关键点提升，只预测残差）→ ExMR（2610.26213 ✅，2026-10-19 刚挂出，把同样思路推广到手和肘、腕）。结论是"整体表示没有用好局部证据"，这和 T-res（小人物重裁）的思路相通。
  • 遮挡评测用的是 3DPW-OC、EgoBody、RICH 这类真实数据，没有逐关节遮挡真值，也没有"遮挡面积 × 持续时间"的剂量控制。本机官方分层得到的 2.3 倍是相关关系，不是因果。

L3. 合成和游戏数据：常用来训练，很少用来诊断

  • 训练用途：GTA-Human（2110.07588 ✅，TPAMI 2024）、BEDLAM2.0（2511.14394 ✅，NeurIPS 2025 D&B：相机运动、可变焦距和变焦，GVHMR 重训后 EMDB 只提升几个百分点）、PoseDreamer（2603.28763 ✅，扩散生成数据 + 难例挖掘）、蹦床体操（2604.01322 ✅，合成极端姿态）。
  • 评测用途：MVMP-HMR（2607.24302 ✅，多视角多人合成基准）、Human3.6M-C（CVPRW 2024，verify_pending，2D→3D lifter 的腐蚀基准，不是视频网格恢复）。
  • 缺口：没找到研究"合成基准上的方法排名能否预测真实基准排名"（sim-to-real 评测效度）的 HMR 工作；也没有人做过视频世界系 HMR 的"遮挡 × 相机 × 人物大小"联合压力测试。

L4. 无真值的质量估计和不确定性：单图有，视频少

  • CUPS（2412.10431 ✅）：视频 HMR + 共形预测，给出覆盖保证。
  • ScoreHypo（CVPR 2024，verify_pending）：给多个假设打分并选择。
  • MHE-Former（2609.10743 ✅，2026-09）：多假设 + 用 VLM 做假设选择。
  • VLM 评审 HMR（2602.19180 ✅，CVPR 2026）：Qwen3-VL-32B 给渲染叠加图打分，用于偏好对齐；它的自我反思阶段要用真值。
  • MotionCritic（2407.02272 ✅，ICLR 2025）：学到的运动感知质量评分，面向生成，不是重建。
  • 缺口：(a) 视频级别"失败了，而且是哪一种失败"的诊断；(b) 在可控剂量下检验这些 GT-free 分数（VLM 评分、重投影误差、不确定性）与真实 3D 误差的相关性，也就是评审器是否在最需要它的条件下失灵。

L5. Agent 和工具编排：2026 年 10 月正热，但没有 3D 真值验证

  • ChatHuman（2405.04533 ✅，CVPR 2025）：单图，学习选工具。
  • AHa-3D（课程参考）：编程 agent 操作仓库，没有定量基准。
  • Agentic Real2Sim（2607.19190 ✅，2026-07）：开源 VLM 驱动 real2sim，含人形运动场景。
  • LiteReality-Agent（2610.01863 ✅，2026-10-01）：把重建写成编程问题，用 observe-edit-verify 框架；核心卖点是"验证机制"。
  • InteractAgent（2610.25649，2026-10）：MLLM 规划和评估，冻结的 MotionLLM 执行，用于运动生成。
  • 缺口：这些系统都声称"验证"提升了可靠性，但没有一篇用 3D 真值检验 agent 的验证判断本身是否正确。

L6. 测试时自适应（TTA）

CycleAdapt（2308.06554 ✅）、DynaBOA（2111.04017 ✅）、语义感知 TTA（2502.10724 ✅，ICML 2025）、长时 TTA（AAAI 2026，verify_pending）。都针对相机系或 3D 姿态模型；没有针对 GVHMR 这类世界系视频模型的，也没有在有真值的游戏域移位上做的。

L7. 自动找失败

PoseExaminer（2303.07337 ✅，CVPR 2023）在人体模拟器里用多智能体 RL 搜失败区域，是单图模型。视频世界系模型的失败搜索空间（遮挡时机、相机转速、人物大小、帧率）还没人做。

L8. 相机和焦距

CameraHMR/HumanFoV（2411.08128 ✅）、Multi-HMR 2 的 FOV 预测、Zolly、BLADE、W-HMR。本机结果 B5（焦距错 1.9 倍 → 深度错 1.85 倍，姿态几乎不变）与这些工作一致；在 GTA 上焦距已知，这一维对姿态不重要，对世界系轨迹和多人相对深度重要。

前排方向详述

I5 验证器什么时候会骗人（分诊第 1）

  • 做法：

    1. 在 GTA 片段上按剂量加扰动：遮挡面积 × 时长、人物缩小、虚拟转镜、故意用错焦距、过度平滑的后处理。
    2. 对每个输出计算一组不看真值的信号：2D 重投影误差、关键点置信度、jitter 和脚滑、测试时增强的分歧、AHa-3D 式的滑动/重投影检查、MotionCritic 分数、本地 Qwen3-VL-8B 看叠加图的打分。
    3. 在每个剂量档里算这些信号和真实 3D 误差（PA-MPJPE、W-MPJPE）的秩相关，画出"相关性随剂量变化"的曲线。
  • 假设：基于 2D 的信号和 VLM 评分在"被挡的肢体被合理地编出来"和"深度错了"这两类失败上看不出问题。所以相关性恰好在最需要验证的条件下塌掉；依赖 verify 步骤的 agent 流程（AHa-3D、LiteReality-Agent）也继承这个盲区。
  • 最小实验：40 段 × 6 种条件，信号计算很便宜，VLM 约 2 个 GPU 小时。
  • 两个方向的结果都能报告：如果相关性一直很高，说明简单验证器够用；如果在某些条件下塌掉，就是 agent 验证步骤的已知盲区。
  • 评审最可能的反对：VLM 的结果可能只反映 8B 模型和提示词的局限，而不是"视觉验证"本身的局限。命名风险："平凡主导"，即简单的关键点置信度在几乎所有条件下都和 3D 误差高度相关。
  • Pilot：跳过，需要 pilot 验证。

I1 输入换真值的误差归因（分诊第 2）

  • 做法：

    1. 对 GVHMR 的每个输入（跟踪框、2D 关键点、关键点置信度、内参、相机角速度）各准备一个 GTA 真值版本。2D 关键点由游戏骨架映射到 COCO-17；置信度用 1−occ。
    2. 逐项替换和两两替换各跑一次（缓存特征，只做推理）。
    3. 按"大/中/小人物 × 有无遮挡"分层，用 Shapley 值把误差分摊到各模块。
  • 假设：小人物的误差主要来自 2D 关键点，而不是时序网络；跟踪失败主导了片段级的离群值。
  • 最小实验：现有 30–48 段，约 2–3 个 GPU 小时（make_oracle_track.py 已经能注入框）。
  • 评审反对 / 命名风险："真值图像特征"不存在，图像特征分支只能当残差；模块之间可能有超可加的交互，分摊结果会不干净。

I7 小人物：分辨率剂量、原因和免训练修复（分诊第 3）

  • 做法：

    1. 按比例缩小整帧（内参同步精确缩放），让同一段动作的人物高度分别为画面的 0.4、0.25、0.15、0.10、0.07。
    2. 结合 I1 的真值替换，判断小人物失败的原因：2D 关键点、图像特征，还是深度歧义。
    3. 试三种免训练修复：在原分辨率下重新紧裁；双三次插值放大；ViTPose 之前用超分（分别只用在 ViTPose 分支或只用在 ViT 特征分支）。
  • 假设：人物高度低于约 0.15 时，2D 关键点成为瓶颈；原图里有像素时，紧裁能救回大部分误差，像素已经丢失时超分救不回来。
  • 最小实验：20 段 × 5 个尺度 × 3 种修复，约 6–8 个 GPU 小时。
  • 命名风险：真正的信息丢失。人物低于 100 px 时肢体只有 2–4 px 宽，哪种修复都没用。
  • Phase 3 之后 executor 在代码里核实的事实（回应查新的 CAUTION）：GVHMR 预处理 hmr4d/utils/preproc/vitfeat_extractor.py:get_batch 和 vitpose.py:extract 默认 img_ds=0.5，即先把整段视频缩小一半，再裁剪放大到 256 给 ViTPose 和 HMR2 特征用（源码注释："img_ds makes the image smaller, which is useful for faster processing"）。1080p 里高度不到 0.15（<162 px）的人，裁剪前就只剩不到 81 px。你们的 GTA 结果都是在默认 0.5 下跑的；gvhmr_eval/run_clip.py 已经支持 --img_ds，但 scratch 上没有任何 _ds1 输出，说明从没用 1.0 跑过。这正是查新评审要求的"GVHMR 处理小人物的具体缺陷"候选。最便宜的判别实验：10 个小人物片段，--img_ds 1.0 对比 0.5，不到 1 个 GPU 小时。如果小人物的 PA-MPJPE 明显下降（比如 ≥10%），I7 就有了一个免训练修复 + 原因定位；如果几乎不变，就排除了"预处理分辨率"这个解释，瓶颈在更后面。两种结果都有信息量。

I3 遮挡剂量与时序桥接长度（分诊第 4）

  • 做法：在 GTA 片段上贴合成遮挡物，控制面积、持续时间、遮挡部位（四肢或躯干）和开始时刻；重新提取 ViTPose 和特征，测 GVHMR 的时序 Transformer 能"桥接"多长的完全遮挡（误差拐点 T\），以及各种后处理能不能把 T\ 延长。
  • 假设：在 0.5–1 秒附近有明显拐点；遮四肢比遮躯干影响更大。这样可以把 2.3 倍的相关结论变成因果曲线。
  • 最小实验：20 段 × 4 种时长 × 3 种面积 × 2 个部位，约 6 个 GPU 小时。
  • 命名风险：立刻崩溃，即 T\*≈1–2 帧，时序模型几乎不桥接，结论退化成逐帧失败报告。合成遮挡物的边缘也不自然。

I6 工具路由的 oracle 余量（分诊第 5，即 P1）

  • 做法：同 P1。4 个修复工具各跑一次并缓存，比较默认、全开、三条规则、Qwen3-VL-8B、真值 oracle 五种路由。
  • 假设：余量集中在尾部（小人物、跟错人），规则路由拿到大部分。
  • 命名风险：oracle 相对最佳固定流程的增益不到 5%，说明选工具只省算力、不提精度。P1 的 go/no-go 就是为这个风险设的。

I16 隐形失败搜索（分诊第 6，高风险、高收益，评审建议给 pilot 名额）

  • 做法：

    1. 把 I3 的扰动生成器参数化为 5 维：遮挡开始帧、时长、位置、虚拟转速、缩放。
    2. 用 CMA-ES 或贝叶斯优化最大化"3D 误差 − λ × 验证器分数"，复用 I5 的验证器。
    3. 加约束"目标关节至少 70% 的帧可见"，排除"全挡住"这种平凡解。
  • 评审认为有说服力的结果：找到可复现的 10–15 帧"局部遮挡 + 转镜"片段，让 3D 误差升到 2.5 倍以上，而 2D 重投影误差变化不到 10%、Qwen3-VL 仍判为"准确"，比如肢体深度翻转或根节点朝向反转。
  • Pilot：评审建议第 3 周做，5 段 × 30 次迭代 ≈ 4 个 GPU 小时。
  • 命名风险：退化最优解，即优化器找到的是打分漏洞，不是真正的隐形失败。

I2 相机转速去混杂（第 7）

  • 做法：动作保持不变，用视角更窄的虚拟相机做纯旋转单应变换，转速 0/15/30/60/90°/s。分别给 GVHMR 静止假设、VO 和真值角速度三种相机输入，和真实基准里"转速越快误差越低"（EMDB-1 ρ=−0.50）的观测结论对比。
  • 命名风险：曲线是平的，因为 GTA 背景纹理清晰，VO 很容易跟上。纯旋转单应也没有视差、运动模糊和卷帘快门。

I9 按可见性加权的后优化（第 8，≈P2）

  • 做法：在 AHa-3D v2 后优化里，把 0.9 的硬阈值换成可见性权重，比较三种权重来源：ViTPose 置信度、GTA 真值 occ（上界）、小型学习头；证据越少，时序先验越强。
  • 命名风险：即使用真值可见性，MPJPE 也只改善不到 2 mm。评审建议把重点放在"知道哪里被挡的价值上界"和帕累托权衡（I19），而不是把加权本身当成算法创新。

I10 世界系测试时自适应（第 9）

  • 做法：每段视频只更新 GVHMR 时序 Transformer 的 LayerNorm 或 adapter（不到 0.5% 的参数），用 2D 重投影 + 触地自监督训练约 20 步；在相同 GPU 时间下，和输出空间后优化（AHa-3D v2）比较。
  • 命名风险：对噪声 2D 灾难性过拟合，在遮挡和小人物上反而更差。

I20 合成评测效度（第 10）

  • 做法：取 6–8 个系统变体（GVHMR 和 GVHMR-BEDLAM2、几种后处理、几种内参设置），分别在 GTA 和真实基准的分层上排名，报告 Kendall τ，以及人物大小、遮挡这些因子斜率的一致性。
  • 命名风险：变体太少，τ 的置信区间很宽；快速转镜、长时遮挡这些真实数据里没有的条件无法验证。

其余方向（简述，详见分诊 trace）

  • I19 帕累托前沿：命名风险是 HTD-Refine 在所有权重下都占优，权衡故事不成立。
  • I18 共形风险控制：命名风险是可以预见的协变量偏移失效，修好它只是标准的加权共形方法。
  • I17 区分自遮挡和外物遮挡的精修器（高风险）：GTA 独有的 occ/self_occ 区分，和 ExMR（10/19）的思路直接相连；命名风险是远端关节的拟合真值噪声。
  • I11 帧率解耦：命名风险是 B7 的现象只是重复帧造成的有限差分伪影。
  • I4 噪声底：命名风险是排名完全不变，结论正确但不够有意思。
  • I13 多人特征污染：命名风险是 I/O 开销大，涂黑别人本身对 ViT 来说就是分布外输入。
  • I15 遮挡微调（P3）：命名风险是灾难性遗忘，原训练数据下不到。

评审发现的硬伤（都接受，进入 refine）

  1. 你们自己的结果文件写过 GTA 的世界系指标和脚滑"不可靠，只作参考"（序列短、常常不动、15 fps、真值是拟合的），但 brief 却把 W-MPJPE、脚滑、jitter、MotionCritic 当作 GTA 上的核心指标。→ 时序和世界系验证器只在 EMDB/RICH（30 fps 动捕）上审计，GTA 只审相机系。
  2. "验证器失明"和"指标不相关"被混在一起：焦距错时 PA-MPJPE 只差 0.7 mm，按 PA-MPJPE 算 GVHMR 根本没失败，验证器说"姿态没问题"就不算撒谎。2D 重投影看不出 f 和 Z 一起缩放，这是透视几何的恒等式，不算新发现。过度平滑配 jitter 是同义反复。→ 每种失败要和对应的 3D 指标配对；这两种"构造出来的失败"不作为主要结果。

  3. 统计缺陷：同一剂量档内，片段之间的差异来自自然差异和真值噪声，重剂量下所有片段都失败，会出现值域受限，相关性和 AUROC 自然塌向随机水平。跨剂量合并时，任何能"看见扰动本身"的输入信号（置信度下降、框变小）都会因为和剂量同变而显得很准。→ 改测：

    • (a) 区分输入代理（框大小、ViTPose 置信度）和输出验证器（重投影、TTA 分歧、VLM 打分等），报告控制输入代理后的偏相关；
    • (b) 同一片段内的成对排序准确率：给同一段视频的两个重建，验证器能否挑出 3D 误差更低的那个。这正是 agent 判断"修复后是否更好"时做的决定，而且片段本身的难度和真值偏差都在比较中抵消；
    • (c) 同时用 ΔE(d) = MPJPE(pred(d), pred(0)) 做目标，避开真值噪声；
    • (d) 用簇 bootstrap 给置信区间，划分 20 dev / 40 test。
  4. 转镜剂量物理上做不到：50° 画面里裁一个更窄的虚拟相机，以 60–90°/s 转动，4–6 帧（15 fps）就扫完整个画面，人物出画。→ I5 不做高速转镜，改用"相机模式失配"（静止假设 vs VO），在 EMDB-2/GTA 上做。这一条同样削弱 I2：I2 只能做 ≤30°/s，或者做来回摆动的抖动，要在报告里如实说明。
  5. 真值噪声循环：14.5 px 的拟合误差会被误判为"重投影验证器失明"。→ 用 ΔE 目标，并且只选人物在动、时长 ≥4 s 的片段。

贡献是否足够

  • 课程项目：足够（强），前提是保留修复选择的评测，并在 EMDB/RICH 已有的 dump 上做真实数据检查。两个课程题目都能覆盖，约 30–45 个 A40 GPU 小时。
  • workshop 论文：介于勉强和扎实之间。"重投影看不出焦距错"和"平滑降低 jitter"会被认为是平凡结论；能发表的是新近提出的验证器（VLM 叠加图评审、MotionCritic、TTA 自洽）存在系统性且互补的盲区，并且在 GTA 上做了因果剂量、在 EMDB/RICH 分层上做了观测验证。

第一个该跑的判别实验（< 3 GPU 小时，2–3 天）

  • 复用缓存：30 段 GTA 的 S0/S1gtK/S0raw 和 EMDB-1 的 17 段，不用重跑 GVHMR。计算输入代理和输出验证器（Qwen3-VL 约 0.5 GPU 小时）。
  • 小型因果剂量：10 个大人物片段（真值噪声最小）× 遮挡 {0, 25%, 50% 四肢} × 缩放 {1.0, 0.5, 0.25}，加一次水平翻转 TTA，约 1.5 GPU 小时。

  • 决策规则：

    • 规则 1：如果验证器对 ΔE 的相关比对拟合真值的相关高 ≥0.15，就把 ΔE 和 EMDB-1 定为并列主要目标。
    • 规则 2：如果输出验证器之间有互补的盲区（例如重投影和 VLM 看不出被挡肢体被编出来，TTA 翻转分歧能看出来），就按完整计划做。如果 ViTPose 置信度单独就达到 |ρ|>0.85，而所有输出验证器在同片段成对排序上都接近随机（AUROC<0.58），就把论点改成："输入置信度能预测 GVHMR 何时失败，但现有的 GT-free 输出验证器判断不了修复是否成功"。这样 P1 的"输入驱动路由 vs 输出驱动验证"就成为主论点。
